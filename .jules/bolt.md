## 2024-10-27 - N+1 Query in Django DetailView
**Learning:** Found a specific N+1 query issue in `OlympicClassroomDetailView` where `olympians` and their associated `team` are accessed in `templates/olympiads/classroom_detail.html` rendering. Using `prefetch_related` along with a custom `Prefetch` containing `select_related` on the original queryset solves this effectively.
**Action:** When working on similar Django apps, look for nested relationships used inside template loops, and fetch them using custom `Prefetch` querysets.
## 2024-10-31 - N+1 Query in Django ListView templates due to context processors
**Learning:** Found N+1 query issue in main templates (`classroom_list.html` and `event_list.html`) where iterating over context processor variables (`sidebar_classes`, etc.) and using `.count()` and `.exists()` causes repeated evaluations per item. Since context processor variables are global, they don't carry annotations from view-specific querysets.
**Action:** When rendering list views, avoid iterating over global context variables for main page logic. Use view-specific context (like `classrooms` from `ClassroomListView`) and apply `.annotate(Count('...'))` on the queryset. In the template, use the annotated field (e.g., `cls.students_count`) instead of evaluating `.count()` or `.exists()` on related managers.
